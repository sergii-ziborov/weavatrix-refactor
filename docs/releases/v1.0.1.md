# Weavatrix Refactor 1.0.1

A dependency release. Nothing in the eleven refactor tools changed: same names,
same schemas, same result states, same `weavatrix.edit-plan.v1` envelope.

## What moved

| Dependency | From | To |
| --- | --- | --- |
| `weavatrix-rust` | 2.3.0 | 2.4.0 |
| `weavatrix-rust-refactor` | 0.1.0 | 0.1.1 |
| `mcport` | 0.3.0 | 0.5.0 |
| `blazingly-json` | 0.1.3 | 0.1.4 |

The engine brings one more read-only tool, `verify_capabilities` — "resolve
declared capabilities against exposed endpoint evidence" — so the catalog is now
54 tools: 43 read-only and 11 refactor.

## mcport 0.5.0 needed a translation

`ToolReply::Success` traded its `structured` boolean for a `ToolPayload`.
`Mirrored` is the faithful reading of the old `true`: it carries
`structuredContent` *and* the text mirror, so a client that reads only `content`
still sees a result. `Structured` would have dropped that mirror and shown such a
client nothing at all.

0.4.0 also began rejecting undescribed tool schemas at registration. That is a
run-time gate rather than a compile error, so it was worth checking rather than
assuming: all 54 tools register and every one of them carries a description.

## blazingly-json 0.1.4 had to be released first

It had been sitting unreleased since 5 August because its own CI was red twice
over — the new word-at-a-time scanner used a bare `size_of`, which only entered
the prelude in Rust 1.80 while the crate declares 1.78, and its publish job
passed `--locked` against a gitignored `Cargo.lock`. Both are fixed upstream and
0.1.4 is on crates.io.
